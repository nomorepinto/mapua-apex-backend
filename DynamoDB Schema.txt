Reorganized schema

ORGANIZATION
PK: ORGANIZATION#uuid
SK: ORGANIZATION#uuid
name: string
signatories: [
  { role: "adviser", signatory_id: "adv001" },
  { role: "cdm",      signatory_id: "cdm001" },
  { role: "dean",     signatory_id: "dean001" }
]
Desk directory for this org (one person per role). Not stored on SIGNATORY.

EVENT
PK: EVENT#uuid
SK: EVENT#uuid
sent_at: timestamp
GSI1PK: ORGANIZATION#uuid
GSI1SK: timestamp

submission_type: string

activity_classification: {
  activity_type: "co-curricular" | "extra-curricular"
  total_org_members: number
}

  id, position_title, first_name, middle_name, last_name, suffix,
  student_number, program_and_year, date_of_submission, department,

NOTIFICATION
PK: SUBMISSION#uuid
SK: NOTIFICATION#timestamp
signatory: SIGNATORY#uuid
notif_type: string

SIGNATORY
PK: SIGNATORY#uuid
SK: SIGNATORY#uuid
name: string
role: "adviser" | "cdm" | "dean" | "osaar" | "admin"
department: string (deans only, e.g. SOIT)
GSI4PK: ROLE#ADVISER | ROLE#CDM | ROLE#DEAN | ROLE#DEAN#{DEPARTMENT} | ROLE#OSAAR | ROLE#ADMIN
GSI4SK: SIGNATORY#uuid

A SIGNATORY item is the person. It has no organization_id.
Who occupies a desk for an org is ORGANIZATION.signatories.
GSI4 is the role index, not an org assignment. ROLE#{ROLE} for adviser, cdm, osaar, admin.
Deans may add a department suffix: ROLE#DEAN#SOIT.

Other items copy the signatory id; they do not join back to SIGNATORY:
  ORGANIZATION.signatories[].signatory_id
  SUBMISSION.current_signatory and GSI2PK (inbox)
  NOTIFICATION.signatory (timeline snapshot)
  APPEALS.signatory_destination and GSI3PK (appeal inbox)
Deleting a SIGNATORY item does not rewrite those copies. Replace a person in
place by keeping the same uuid (PUT name / role / department). A new uuid
leaves in-flight papers, open appeals, org desks, and Cognito custom:signatory_id
pointing at the old id.

Routing is application logic, not a field on SUBMISSION. Extra-curricular +
has_reservation → Adviser then CDM from ORGANIZATION.signatories; every other
combination is Adviser only. current_signatory / GSI2PK hold whoever has the
paper now. On approve, the resolver reads the org desk list again to pick the
next id (or drop GSI2 when the sequence is done). Appeals go to the org Dean.
